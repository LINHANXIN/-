## 1. 核心规则

### 1.1 写作铁律
1. **克制第一** — 不煽情，不说教。情绪藏在细节和动作里。
2. **短句为主** — 一个段落一件事。对话简洁，大量留白。
3. **具体可触** — 不说"他很感动"，写"他的手停了一下"。
4. **尾韵留白** — 每章结尾不做总结。最后一句像一扇虚掩的门。
5. **无旁白叙述** — 不插入作者的议论。用人物的行动和感知展开。
6. **不重复意象** — 同一个比喻在五章内不可重复使用。
7. **前后一致** — 任何细节必须与已发布内容和人物设定一致。
8. **禁用分隔符与破折号** — 正文中不得出现 `---`、`***`、`===` 等 Markdown 分隔线，也不得出现 `——`（破折号）。场景转换用空行（两个换行）自然过渡，不加任何符号。需要停顿或转折时用逗号、句号或直接换行，不用破折号。

### 1.2 作者有话说规范
- 第一人称，像和读者朋友聊天
- 点出本章一个隐藏细节或暗线，但不说破
- 可以提前轻微剧透（"后面你会看到..."），制造期待
- 不解释剧情，不做阅读理解
- 不用表情包、不卖萌
- 字数严格≤300字

### 1.3 文风标尺
```
✅ 好的句子：
"他的手停了一下。只有一下。然后他继续拔草，像是没听到。"
"四个字，没有标点。"
"不是笑。是一种期待的表情。"
"他蹲下来。"

❌ 避免的句子：
"那一刻，他深深地感到了生命的重量。"
"他的内心涌起一股难以言喻的感动。"
"夕阳像一首诗一样洒落在大地上。"
"他的眼泪如同断了线的珍珠般滚落下来。"
```

## 2. Agent 流水线

每写一章，依次调用以下 8 个独立 Agent（subagent）。前一个的输出是后一个的输入。
每个 Agent 已定义为独立的 `.md` 文件，位于 `~/.copilot/agents/`。

### 流水线顺序

```
napianshanpo-planner  →  章节计划（500字结构化文档）
       ↓
napianshanpo-writer   →  初稿（3000-5000字正文）
       ↓
napianshanpo-critic   →  审查报告（问题清单，PASS/FAIL）
       ↓
napianshanpo-improver →  第二稿（修复问题后的正文）
       ↓
napianshanpo-styler   →  第三稿（去AI化、节奏打磨后的正文）
       ↓
napianshanpo-qa       →  质量判定（PASS/FAIL）
       ↓                    ↓ FAIL → 退回 improver 或 styler
napianshanpo-memory   →  更新追踪文件
       ↓
napianshanpo-publisher→  保存正文.txt + 作者有话说.txt
```

### 调度规则
1. **严格顺序执行** — 上一个 Agent 完成后才调下一个
2. **QA FAIL 回退** — 如果 QA 判定 FAIL，根据其建议退回给 Improver 或 Styler，然后从退回点重新走流水线
3. **最多回退 2 次** — 同一章回退超过 2 次，强制 PASS 并标记需要人工复查
4. **每个 Agent 只做自己的事** — 不越界

## 4. 工作流触发

### 写新章节
用户说："写第X章" / "续写" / "写下一章"
→ 执行完整 8-Agent 流水线

### 修改章节
用户说："修改第X章" / "这段不好"
→ 只执行 Critic → Improver → Styler → QA → Memory → Publisher

### 查看规划
用户说："接下来写什么" / "查看进度"
→ 读取 章节记忆.txt，找到最后一章，显示后续 5 章规划

### 查看伏笔
用户说："伏笔" / "哪些没回收"
→ 读取 伏笔追踪表.txt，列出未回收伏笔
